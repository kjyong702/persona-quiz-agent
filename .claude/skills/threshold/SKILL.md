## 왜 둘로 나뉘어 있나

임계값을 정하려면 **같은 데이터에 값만 바꿔 수십 번 계산**해야 한다.
그때마다 임베딩을 다시 부르면 값이 미세하게 흔들려 **비교 대상이 안 된다.**
그래서 한 번 재고 캐시한다.

| | 비용 | 언제 |
|---|---|---|
| `scripts.measure` | **유료** | 앵커나 평가셋이 바뀌었을 때만 |
| `scripts.analyze` | 무료 (캐시) | 몇 번이든 |

## 순서

```bash
uv run python -m scripts.seed                          # 앵커 적재 (모델이 바뀌었으면 필수)
uv run python -m scripts.measure                       # 유사도 측정 (유료, 1회)
uv run python -m scripts.analyze --sweep --holdout     # 임계값 후보 (무료)
```

## 값을 고를 때

**기준은 false accept 0건이다.** 오답을 정답으로 확정하는 것은 LLM이 고칠
기회조차 없어서 **호출 비용으로 살 수 있는 종류가 아니다.**

**그리고 최적값을 그대로 쓰지 않는다.** 최적값은 그 데이터에서만 오류 0이고
**경계에 가장 가까운 샘플이 하나만 더 나와도 깨진다.**

```
상한: 부정문 제외 오답의 최대값보다 충분히 위
하한: 정답의 최소값보다 충분히 아래
```

여유를 얼마나 살지는 LLM 위임 비율과의 교환이다. **양쪽에 같은 원칙을 적용한다.**
한쪽만 여유를 주면 반대쪽이 경계에 붙은 채로 남는다.

## `--holdout`을 반드시 본다

같은 데이터로 고르고 같은 데이터로 보고하면 과적합이다.
**문항 단위로 나눠야 한다.** 답변 단위로 나누면 같은 문항의 다른 답변이
train과 test에 걸쳐 들어가 누수가 생긴다.

## 바꾼 뒤

1. `.env`와 `.env.example` 양쪽 (**`.env`가 코드 기본값을 덮어쓴다**)
2. `docs/notes/threshold-measurement.md`에 차수를 붙여 기록
3. **`/eval`로 판정 프롬프트를 다시 잰다.** 위임 대상이 바뀌었기 때문이다
