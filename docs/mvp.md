# MVP 정의

## 문제

퀴즈 서비스에서 자연어 주관식 답변을 판정하려면 선택지가 두 개다. 문자열 매칭은 표현이 조금만 달라도 오답 처리하고, 모든 답변을 LLM에 보내면 비용이 크고 판정이 흔들린다. 이 프로젝트는 그 사이의 답인 **하이브리드 판정**(임베딩 유사도 1차, 애매한 구간만 LLM 2차)을 구현하고, 판정 품질을 감으로 확인하는 대신 **평가 파이프라인으로 측정**한다.

## 범위

### 포함 (MVP)

1. 퀴즈 세트와 문제: 시드 JSON으로 로드 (상식 퀴즈 2세트, 세트당 문제 10개 내외)
2. 페르소나 호스트: 프로필(이름, 성격, 말투, 리액션 성향)에서 시스템 프롬프트 자동 생성, 문제 출제/정답 오답 리액션 멘트 생성
3. 퀴즈 세션: 시작, 다음 문제 받기, 답변 제출, 진행 상태 조회
4. 하이브리드 판정: 임베딩 코사인 유사도 상하한 임계값으로 즉시 판정, 중간 구간은 LLM 2차 판정, 임베딩 실패 시 LLM 단독 폴백. 판정마다 사용 경로(embedding/llm/fallback)와 유사도 기록
5. 평가 파이프라인 (promptfoo):
   - 판정 정확도: 라벨링된 답변 데이터셋(정답 표현 변형, 오답, 애매 케이스)에 대한 정확도 측정
   - 페르소나 품질: 프롬프트 버전별 응답 회귀 테스트 (말투 유지, 정답 유출 금지 등 규칙 검증)
6. 동시성과 레이트 리밋 대응: 동시 인플라이트 상한과 레이트 리미터, Retry-After를 존중하는 재시도. 부하 스크립트로 429를 재현하고 대응 전후를 측정해 기록
7. 배포 구성: 설정과 시크릿을 코드에서 분리하고 긴 LLM 호출에 맞는 타임아웃 체인을 구성. 컨테이너로 실행 가능한 상태

### 제외

- 회원/인증, 관리자 화면, 프론트엔드 (API 서버만)
- 멀티턴 대화 기억 (세션 상태는 DB로 관리, LLM 컨텍스트는 문제 단위)
- 클라우드 실배포와 IaC (컨테이너 실행 가능 상태까지가 범위. 실제 프로비저닝은 후속)

## 성공 기준

- 판정 데이터셋 정확도가 문자열 매칭 베이스라인보다 높고, LLM 호출 비율이 전체 답변의 일정 수준 이하 (임계값 튜닝 근거를 평가 리포트로 남김)
- 페르소나 프롬프트를 수정해도 promptfoo 회귀 테스트로 품질 저하를 잡아낼 수 있음
- **동시 요청이 몰려도 429로 인한 실패가 재시도와 흐름 제어로 흡수된다.** 대응 전후 성공률과 지연을 수치로 비교할 수 있음
- **판정 결과가 재현 가능하다.** 임베딩 모델과 템플릿 버전이 기록되어 있어 "이 점수가 어떤 조건에서 나온 것인지"를 사후에 특정할 수 있음
- 문서(mvp, db-schema, api-spec)와 구현이 일치
