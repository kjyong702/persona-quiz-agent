# 배포 구성

> 재현
> ```
> docker build -t persona-quiz .
> OPENAI_API_KEY=... docker compose up -d
> docker compose exec api python -m scripts.seed    # 앵커 적재
> curl localhost:8000/readyz
> ```

## 타임아웃 — 상한이 아예 없었다

호출 단위 타임아웃(`llm_timeout_seconds=20`)만 있고 **요청 전체 상한이 없었다.**
재시도가 4회에 백오프가 붙으므로 실제로는 이렇게 된다.

```
호출 1회 최악  : 4회 x 20초 + 백오프 3.5초 = 83.5초
판정 한 건     : 임베딩 + LLM 둘 다 부르므로 최악 167초 (2.8분)
uvicorn        : 요청 타임아웃 없음 (timeout_keep_alive=5는 유휴 연결용이다)
```

**미들웨어에 `asyncio.timeout`으로 상한을 걸었다** (기본 30초).

### 앱이 앞단보다 먼저 끊는다

관례에는 반대 이야기도 있다. 프록시를 앱보다 짧게 잡아 **프록시가 먼저 포기하게**
하면 클라이언트가 받는 에러 메시지가 깔끔하다는 쪽이다.

**여기서는 앱이 먼저 끊는다.** 이유가 둘이다.

| | 프록시가 먼저 끊으면 | 앱이 먼저 끊으면 |
|---|---|---|
| 클라이언트 | 504 | **도메인 에러 코드** (`REQUEST_TIMEOUT`) |
| 진행 중이던 LLM 호출 | **계속 돈다** | `asyncio.timeout`이 취소를 전파해 **같이 끊긴다** |

앞단이 먼저 끊으면 **아무도 안 기다리는 응답에 돈을 쓰고 그 사실이 어디에도 안 남는다.**
앞단을 둘 때는 `request_timeout_seconds`보다 **길게** 잡아야 한다.

### 설정끼리 모순되면 부팅 때 알려준다

재시도 예산(167초)이 요청 상한(30초)을 넘는다. 넘는 것 자체는 잘못이 아니지만
**재시도가 설정한 횟수만큼 못 도는 것을 모르는 채 쓰는 것**이 문제다.
부팅 로그에 `config.retry_budget_exceeds_timeout`으로 남긴다.

## 헬스체크 — 둘을 나눈다

| | 무엇을 묻나 | 실패하면 |
|---|---|---|
| `/healthz` | 프로세스가 **살아 있나** | 오케스트레이터가 **재시작**한다 |
| `/readyz` | **일할 수 있나** | 트래픽만 안 보낸다 |

**재시작으로 고쳐지지 않는 문제는 liveness가 아니다.** 앵커가 없다고 재시작하면
같은 상태로 다시 떠서 루프에 빠진다. 그래서 Docker `HEALTHCHECK`도 `/healthz`를 쓴다.

`/readyz`가 보는 것

```json
{"ready": false, "checks": {
  "anchors": 0, "anchors_ok": false,
  "index_stamp": {"expected": "...", "actual": "...", "ok": true},
  "judge_prompt": "judge.v3", "judge_model": "gpt-4o-mini-2024-07-18",
  "api_key": "3f2db68a"}}
```

**인덱스 도장을 여기서 대조한다.** 판정마다 걸리면 사용자가 오류를 보지만
여기서 걸면 **트래픽을 받기 전에** 막힌다.

## 도장 검사가 실제 인덱스에서는 작동하지 않았다

`/readyz`를 만들고 모델만 바꿔 띄웠는데 **드리프트가 안 잡혔다.**
`ready: true`에 `actual: "match"`가 나왔다.

원인은 **도장이 애초에 안 찍혀 있었다**는 것이다.

```
컬렉션 metadata : hnsw:space 만 있음      <- 도장 없음
레코드 metadata : embedding_model 있음    <- 여기엔 있다
```

Chroma의 `get_or_create_collection`은 **컬렉션이 이미 있으면 넘긴 metadata를
무시한다.** 그래서 도장을 넣는 코드를 나중에 추가하면 **기존 인덱스에는 영영 안 찍힌다.**
단위 테스트는 매번 새 컬렉션을 만들어서 이걸 못 잡았다.

**레코드 metadata로 대조하도록 바꿨다.** `replace_anchors`가 매번 새로 쓰므로
항상 최신이고, **그 필드들은 처음부터 있었다.** 기록만 하고 아무도 안 읽었을 뿐이다.

### 그리고 도장을 호출자가 찍고 있었다

바꾸고 나니 테스트 4건이 깨졌다. 테스트 앵커에 도장이 없었기 때문이다.
`seed.py`는 손으로 넣고 테스트는 안 넣었다.

**도장 찍기를 저장소 책임으로 옮겼다.** `replace_anchors`가 모든 레코드에 찍는다.
**기억해야 지켜지는 규칙은 언젠가 안 지켜진다.**

## Docker — 빌드해보고 나서야 알았다

정적 검증은 전부 통과했다. `.dockerignore`가 `.env`를 막는 것도, `uv.lock`이
있는 것도 확인했다. **그런데 띄우니 바로 죽었다.**

```
sqlalchemy.exc.OperationalError: (sqlite3.OperationalError) unable to open database file
```

**볼륨 `/data`가 root 소유인데 프로세스는 uid 1000이다.** 에러 메시지에
권한이라는 말이 없어서 원인이 바로 안 보인다.

```dockerfile
RUN mkdir -p /data && chown app:app /data
VOLUME ["/data"]
```

Docker는 **비어 있는 named volume을 마운트할 때 이미지의 해당 경로 내용과 소유권을
복사한다.** 그래서 이미지에서 미리 만들고 `chown`해두면 볼륨도 따라온다.
**bind mount는 이 규칙이 적용되지 않으므로** 호스트 쪽에서 맞춰야 한다.

### 실측 결과

| | 결과 |
|---|---|
| 이미지에 `.env`/`tests` 포함 | **없음** |
| 실행 사용자 | `uid=1000(app)` — 루트 아님 |
| 컨테이너 기동 | `Up (healthy)` |
| 시드 전 `/readyz` | **503** (앵커 0) |
| 시드 후 `/readyz` | **200** (앵커 121) |
| 재시작 후 | **200** (앵커 121 유지) |
| **볼륨 없이 기동** | **503** (앵커 0) |

**마지막 줄이 볼륨이 필요한 이유다.** SQLite와 Chroma가 둘 다 파일이라
컨테이너 레이어에 쓰이고, 컨테이너를 새로 만들면 날아간다. 그러면 판정이 전부
LLM 폴백으로 가서 비용이 몇 배가 된다.

## 이미지 구성

- **멀티스테이지**: 빌드 도구와 uv가 최종 이미지에 안 남는다
- **의존성 층 분리**: `pyproject.toml`과 `uv.lock`만 먼저 복사한다. 소스를 같이 넣으면
  코드 한 줄만 고쳐도 의존성을 다시 받는다
- **`--frozen`**: 잠금 파일을 갱신하지 않는다. 빌드가 조용히 다른 버전을 쓰면
  로컬에서 통과한 평가가 이미지에서는 다른 결과를 낸다
- **`--no-dev`**: 테스트 의존성은 런타임에 필요 없다
- **비루트 실행**

## 남은 것

- **오케스트레이터 설정이 없다.** k8s 매니페스트나 ECS 태스크 정의는 안 만들었다.
  `/readyz`를 readiness probe에 연결하는 것은 그쪽 몫이다
- **앵커 적재가 수동이다.** `docker compose exec`으로 따로 돌려야 한다.
  init 컨테이너나 부팅 훅으로 옮기면 자동화되지만, 그러면 **매 배포마다 임베딩
  비용이 난다.** 지금은 명시적으로 돌리는 쪽을 택했다
- 리버스 프록시 설정 예시가 없다. 타임아웃을 앱보다 길게 잡으라는 것만 문서에 있다
- 이미지 취약점 스캔, SBOM 없음
