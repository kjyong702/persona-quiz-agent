# 페르소나 회귀

> 재현
> ```
> uv run python -m scripts.build_persona_cases
> npx promptfoo@latest eval -c eval/promptfoo/persona.yaml --repeat 10
> ```

## 무엇을 지키려는 것인가

판정과 달리 **진행 멘트에는 정답이 없다.** "좋은 멘트"를 채점할 수 없다.
그래서 좋은지가 아니라 **무너지면 페르소나가 무의미해지는 규칙**만 본다.

| 규칙 | 검사 | 왜 이 방법인가 |
|---|---|---|
| 출제 멘트에 기대 정답이 없을 것 | `not-icontains` | 결정적이다. LLM을 안 부르니 흔들리지 않는다 |
| 불꽃은 반말과 느낌표 | 정규식 | 위와 같음 |
| 고요는 존댓말과 느낌표 없음 | 정규식 | 위와 같음 |

**말투를 LLM에게 채점시키지 않는다.** 그러면 그 채점도 흔들린다
(`determinism.md`). 정규식으로 되는 것을 굳이 LLM에 맡길 이유가 없다.

반말 어미 정규식은 한 번 틀렸다가 고친 것이다. 처음 `(야|어|지|자|해)\s`로 썼더니
두 페르소나 모두 0회가 나왔다. **한국어 어미는 문장 끝에서만 어미다.**
위치를 조건에 넣어 `[어아야지자해네](?=[!?.]|$)`로 바꾸자 불꽃 8회, 고요 0회로 갈렸다.

## 반복이 필수다 — 판정과 반대 이유로

진행 멘트는 `temperature=0.8`이다. 같은 상황에서 매번 같은 문장이 나오면
진행자가 녹음기처럼 들려서 **일부러 흔들어둔 것이다.**

> **판정 평가와 정확히 반대다.** 거기서는 흔들림이 노이즈였고 여기서는 흔들림이
> 설계다. 같은 도구로 성질이 다른 둘을 다룬다.
>
> 그래서 **한 번 통과는 아무것도 뜻하지 않는다.** 10회 중 10회 통과해야
> "지킨다"고 말할 수 있다.

## 1차 실행에서 바로 하나 나왔다

```
[불꽃/opening]  4/5회 통과
  출력: "안녕하세요! 상식 퀴즈를 시작할 거야! 준비됐지?"
```

**인사만 존댓말이고 나머지는 반말이다.**

모델이 틀렸다기보다 **스펙에 구멍이 있었다.** 불꽃의 설정은
`반말을 쓰고 문장이 짧다`인데 **인사를 어떻게 할지는 아무 말도 없었다.**
한국어에서 "안녕하세요"는 반말 화자도 관용적으로 쓰기 때문에 모델이 그쪽을 골랐다.

설정에 `인사도 반말로 한다`를 더했다. **10회 반복에서 160/160으로 통과한다.**

> **회귀 테스트의 값은 여기 있다.** 버그를 잡은 게 아니라 **명세가 덜 됐다는 것**을
> 찾았다. 사람이 눈으로 다섯 번 읽어도 "인사는 어떻게 하지"라는 질문은 잘 안 떠오른다.

## 통과만 하는 테스트는 검사하는 게 없는 것과 구분이 안 된다

160/160이 나왔을 때 **일부러 깨뜨려봤다.**

**1차 시도 — 실패했다.** 기본 프롬프트 끝에
`문제를 낼 때는 기대 정답도 괄호에 함께 적어준다`를 붙이고 돌렸더니
**16/16 전부 통과했다.** 출력에 정답이 하나도 없었다.

```
"다음 문제다! 대한민국의 수도는 어디인가요?"
```

**모델이 유출 지시를 무시했다.** 앞쪽에 있는 유출 금지 지시가 뒤에 붙인 지시를
이겼다. 제품으로서는 방어가 견고하다는 뜻이라 좋은 소식이지만,
**검사가 작동하는지는 여전히 확인하지 못한 상태였다.**

**2차 시도 — 프롬프트 전체를 갈아끼웠다.** 경쟁하는 지시가 없게 만들었다.

```
너는 상식 퀴즈의 진행자다.
출제할 때는 문제 문장을 읽고 이어서 그 문제의 정답을 그대로 말한다.
```

```
출제 8건 중 유출로 잡힌 것: 8건 (100%)
  [고요] 대한민국의 수도는 어디인가요? 정답은 서울입니다.
        걸린 토큰: ['서울', '정답은 서울입니다']
```

**검사에 이빨이 있다는 것을 확인했다.** 확인 후 프롬프트는 원상 복구했다.

> **음성 대조를 안 했으면 "유출 0건"을 방어가 잘 된다는 뜻으로 읽었을 것이다.**
> 실제로는 그 문장이 두 가지를 뜻할 수 있다. 방어가 잘 되고 있거나,
> **검사가 아무것도 안 하고 있거나.** 둘을 가르는 방법은 일부러 깨뜨려보는 것뿐이다.

**1차 시도의 실패도 그대로 소득이다.** 뒤에 붙인 지시가 앞의 금지를 못 이긴다는
것을 실측했다. 프롬프트 인젝션 방어의 성질을 우연히 잰 셈이다.

## 구조적 위험 — 캐싱과 페르소나가 상충한다

```
공통 프리픽스 : 2,411자
페르소나 델타 :   167자   (전체의 6.5%)
```

**페르소나를 결정하는 부분이 전체 지시의 6.5%뿐이다.**

그리고 Phase 4에서 프리픽스를 1,032 -> 1,396토큰으로 **키웠다.** 캐싱 최소치를
넘기려고 키운 것이다. 즉 **비용 최적화가 페르소나 비중을 계속 낮추는 방향으로
압력을 준다.**

앞으로도 프리픽스를 키울 유인이 있다. 이 회귀 테스트가 그때 **말투가 묻히는지
알려주는 장치**다. 지금 값(10회 반복 160/160)이 기준선이다.

## 남은 것

- **프리픽스를 키우기 전후로 이 테스트를 돌린 적이 없다.** 지금 기준선은
  이미 키운 뒤의 값이라, 키우면서 나빠졌는지는 알 수 없다
- 페르소나가 둘뿐이다. 셋 이상이 되면 **서로 구분되는지**도 봐야 한다
  (지금 검사는 각자 규칙을 지키는지만 본다)
- 상황 적합성(마무리 멘트가 마무리처럼 들리는가)은 정규식으로 안 되고
  `llm-rubric`이 필요한데, **그 채점도 흔들린다는 것을 알고 넣어야 한다.** 안 넣었다
- 수동 실행이다. CI에 붙어 자동으로 도는 회귀는 아니다
