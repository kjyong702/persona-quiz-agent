# 임계값 1차 측정 결과

> 측정: 평가셋 372건 · 앵커 58건 · `text-embedding-3-small` · `norm-v1`
> 재현: `uv run python -m scripts.seed && uv run python -m scripts.measure && uv run python -m scripts.analyze --sweep`

이 프로젝트에서 **유사도 분포를 처음 실제로 본 기록**이다. 그전까지 임계값
`0.82 / 0.55 / margin 0.05`는 근거 없이 찍은 값이었고, 이 문서가 그 근거를 대체한다.

## 한 줄 요약

**임베딩 유사도만으로는 이 문제를 깨끗하게 가르지 못한다.** 정답의 최소값(0.087)이
오답의 최대값(0.926)보다 한참 아래라 두 분포가 거의 전 구간에서 겹친다.


**정답 하위 25%와 오답 상위 25%가 완전히 뒤섞여 있다.** 이 구간은 어떤 임계값으로도
못 가른다.

## 2. margin은 한 번도 발화하지 않았다

```
상한(0.82) 통과: 111건
그중 margin(0.05) 미달로 LLM행: 0건
```

**설계 단계에서 예측한 그대로다** (`build-log.md`의 🔵 항목 참고). `rival`은 다른
문항 앵커 중 최고값인데, 20문항의 앵커가 서로 의미적으로 떨어져 있어 한 답변이
두 문항에 동시에 가까워지는 일이 일어나지 않는다.

`_is_confident_correct` 주석이 주장하던 정당화 — "몰라요" 같은 답변이 상한을
통과하므로 margin이 필요하다 — 도 **반증됐다.** 회피성 12건의 중앙값은 0.256으로
상한 근처에도 못 온다. 애초에 하한에서 끊긴다.

> **결론: 지금 margin 장치는 코드에 있을 뿐 아무 일도 하지 않는다.**

## 3. 현재 임계값의 성적

```
upper=0.82  lower=0.55  margin=0.05
임베딩 확정 270건 (73.6%)  ·  LLM 위임 97건 (26.4%)
❌ false accept 25건   (오답을 정답으로 확정)
❌ false reject 49건   (정답을 오답으로 확정)
```

**임베딩이 혼자 확정한 270건 중 74건(27%)이 틀렸다.** 그리고 이 오류는 LLM이
고칠 기회조차 없다.

대표 사례:

| 유형 | 유사도 | 답변 |
|---|---|---|
| FA | 0.842 | "세종대왕 아닙니다" |
| FA | 0.863 | "4년마다가 아니에요" |
| FA | 0.837 | "에베레스트산이 아니라던데요" |
| FR | 0.518 | "음 이거 초등학교 때 배운 거 같은데 우리나라 수도는 서울이고..." |
| FR | 0.343 | "조선시대에 한양이라고 부르던 그 도시요" |

**부정문이 예상대로 새고 있다.** 1차 감사에서 지적됐던 그 항목이다.

## 4. 스윕 — 안전한 임계값의 대가

false accept를 0으로 만들려면 **상한을 0.94까지** 올려야 한다.

| upper | lower | LLM 위임 | FA | FR |
|---|---|---|---|---|
| 0.94 | 0.70 | 28.6% | 0 | 66 |
| 0.94 | 0.62 | 36.8% | 0 | 56 |
| **0.94** | **0.20** | **78.5%** | **0** | **4** |

**오류를 거의 없애려면 LLM 위임이 78.5%가 된다.** 하이브리드가 아끼는 호출이
21.5%로 줄어든다.

## 무엇을 배웠나

**"LLM을 언제 부르지 않을 수 있는가"에 대한 답이 처음 수치로 나왔다.
그리고 그 답은 내가 설계할 때 기대한 것보다 훨씬 작다.**

원인은 임베딩이 재는 것이 의미가 아니라 표층 유사성이기 때문이다. 이 데이터가
그걸 두 방향으로 보여준다.

- **부정문**: 뜻이 정반대인데 유사도 0.926까지 나온다. 토큰 몇 개 차이라서
- **패러프레이즈**: 뜻이 같은데 유사도 0.340이다. 겹치는 토큰이 없어서

즉 **틀린 걸 맞다고 하고 맞는 걸 틀렸다고 하는 실패가 동시에 일어난다.**
한쪽만이면 임계값 이동으로 풀 수 있는데 양쪽이라 그게 안 된다.

## 다음 선택지 (아직 정하지 않음)

| 안 | 내용 | 대가 |
|---|---|---|
| A | 임계값을 0.94 / 0.20으로 확정 | 안전하지만 LLM 78.5%. 하이브리드의 이득이 작아진다 |
| B | 앵커를 늘린다 (문장형, 패러프레이즈 앵커 추가) | 정답 하단을 끌어올릴 수 있다. 앵커 관리 비용 증가 |
| C | margin 장치를 걷어낸다 | 코드가 정직해진다. 지금 아무 일도 안 하므로 |
| D | 부정 표현 감지 시 상한 경로 우회 | 규칙 기반이 섞인다 |

**B가 유망해 보인다.** 정답-표준형과 앵커2번이 전부 1.000인 것은 **앵커와 표현이
맞으면 완벽하게 잡힌다**는 뜻이라, 앵커의 표현 다양성을 늘리면 정답 하단이
올라갈 여지가 있다. 다만 그것도 재봐야 안다.
