# 평가 결과

> 재현
> ```
> uv run python -m scripts.seed          # 앵커 적재
> uv run python -m scripts.measure       # 유사도 측정 (유료, 1회)
> uv run python -m scripts.analyze --sweep --holdout   # 임계값 분석 (무료)
> uv run python -m scripts.normlab       # 정규화와 패러프레이즈
> uv run python -m scripts.personalab    # 페르소나 회귀
> ```

측정과 분석을 나눈 이유는 `scripts/measure.py` 독스트링에 있다. 요약하면
임계값을 정하려면 같은 데이터에 값만 바꿔 수십 번 계산해야 하는데, 그때마다
임베딩을 다시 부르면 값이 미세하게 흔들려 비교 대상이 안 된다.

## 데이터셋

`eval/dataset.json` **372건**. 카테고리 20종, 정답 168 / 오답 204.
사람 검수 대기 113건. 라벨은 사람 채점관 기준이고 전건이 적대 검증을 거쳤다.

구축 과정은 커밋 `data: 판정 평가용 라벨링 데이터셋 1차`와 `2차 병합` 참고.
**1차만으로는 측정이 안 됐다** — margin 프로브가 구조적으로 0이 나오고,
정답이 전부 분포 상단에 뭉쳐 상한을 낮출 근거가 없었다. 2차에서 채웠다.

## 1. 판정 정확도와 임계값

확정값 **`upper=0.92 / lower=0.26`**. 전 과정은 `docs/notes/threshold-measurement.md`.

| 단계 | FA | FR | LLM 위임 |
|---|---|---|---|
| 시작 (근거 없이 찍은 값) | 25 | 49 | 26.4% |
| B 앵커 확충 (58 -> 121) | 25 | 27 | 28.9% |
| D 부정 표현 라우팅 | 11 | 27 | 32.7% |
| C margin 제거 | 11 | 27 | 32.7% |
| **A 임계값 확정** | **0** | **0** | 69.5% |

**기준은 false accept 0건이다.** 오답을 정답으로 확정하는 것은 LLM이 고칠
기회조차 없는 오류라 호출 비용으로 살 수 있는 종류가 아니다.

**과적합을 검증했다.** 문항 단위 홀드아웃에서 train FA 0 FR 0 -> test FA 0 FR 2.
가장 나쁜 오류(FA)는 처음 보는 문항에서도 막히지만 **FR은 "이 데이터에서 0"이지
"항상 0"이 아니다.**

## 2. 정규화 템플릿 (`norm-v1`)

`render()`가 문자열을 실제로 바꾸는 **34건**을 원문/정규화 양쪽으로 임베딩해 비교했다.

| | 건수 | 평균 유사도 변화 |
|---|---|---|
| **정답** | 18 | **+0.1725** |
| 오답 | 11 | +0.0150 |

**의도대로 작동한다.** 정답은 크게 오르고 오답은 거의 안 움직인다.

가장 큰 변화

| 답변 | 원문 | 정규화 후 | |
|---|---|---|---|
| `ＫＲＷ` (전각) | 0.324 | **1.000** | +0.676 |
| `ＲＧＢ` | 0.457 | **1.000** | +0.543 |
| `하지!` | 0.545 | **1.000** | +0.455 |
| `ㅇㅇ` (오답) | 0.337 | **0.172** | **-0.165** |

마지막 줄이 흥미롭다. `ㅇㅇ` 같은 자모 답변은 **오히려 내려간다.**
NFKC가 호환 자모를 초성 자모로 바꾸면서 앵커에서 더 멀어진다.
**오답이 내려가는 것도 좋은 방향**이라 정규화가 양쪽으로 일하고 있다.

> **정규화의 목적은 유사도를 올리는 것이 아니라 표기 차이로 생기는 흔들림을
> 없애는 것이다.** 전각이든 반각이든, 느낌표가 붙든 안 붙든 같은 값이 나와야
> 임계값이 의미를 가진다.

## 3. 패러프레이즈 불변성 — 지켜지지 않는다

**이 판정 방식의 근본 한계가 여기서 수치로 나온다.**

`pair_id`로 묶인 정답 패러프레이즈 **20쌍**을 봤다. 같은 뜻을 다르게 쓴 답변들이다.

| | 값 |
|---|---|
| 쌍 안의 유사도 폭 (중앙값) | **0.495** |
| 최대 폭 | **0.736** |
| **다른 경로로 갈라진 쌍** | **14/20 (70%)** |

**같은 뜻인데 하나는 즉시 정답 확정되고 다른 하나는 LLM으로 간다.**

```
[q3-sejong]
  정답확정  1.000  세종
  LLM      0.576  만 원짜리 지폐에 얼굴 그려져 있는 임금님이요
  LLM      0.344  학교 다닐 때 배운 걸 떠올려 보면 조선의 네 번째 임금인 세종대왕이...

[q2-jupiter]
  정답확정  1.000  Jupiter
  정답확정  0.937  주피터요
  LLM      0.452  천문학 다큐에서 봤는데 고리 있는 토성보다도 훨씬 큰 목성...
```

우리 임계값 구간은 `0.26 ~ 0.92`로 폭이 0.66인데, **같은 뜻의 답변들이 평균
0.495만큼 벌어진다.** 구간 폭의 4분의 3이다. 갈라지지 않는 게 이상하다.

### 이것이 뜻하는 것

**임베딩 유사도는 "뜻이 같은가"가 아니라 "표현이 닮았는가"를 잰다.**
이 문서의 다른 측정들도 전부 같은 사실의 다른 얼굴이다.

| 측정 | 같은 사실의 다른 얼굴 |
|---|---|
| 부정문 0.926 | 뜻이 반대인데 표현이 닮아서 높다 |
| 패러프레이즈 폭 0.495 | 뜻이 같은데 표현이 달라서 벌어진다 |
| 정답 최소 0.087 vs 오답 최대 0.926 | 두 분포가 겹친다 |

**그래서 하이브리드가 필요하고, 동시에 하이브리드가 아끼는 폭이 제한된다.**
LLM 위임 69.5%라는 숫자가 여기서 나온다.

### 개선 방향 (이번 사이클에서는 하지 않음)

바이인코더의 구조적 한계라 임계값이나 앵커로는 못 푼다.
**크로스 인코더나 NLI 모델을 임베딩과 LLM 사이에 넣는 3단 구조**가 표준 해법이다.
근거는 `docs/notes/threshold-measurement.md`의 "남은 것" 절.

## 4. 페르소나 회귀

`scripts/personalab.py`. 상세는 `docs/notes/prompt-caching.md`.

| 항목 | 결과 |
|---|---|
| **정답 유출** | 18건 중 **0건** |
| 말투 분리 (불꽃/고요) | 느낌표 12/0, 존댓말 0/10, 반말 8/0 |

**두 경로의 방어 강도가 다르다는 것을 기록해둔다.**

- **리액션**: 입력에 문제도 정답도 없다. **프롬프트에 없으면 흘릴 수 없다** (구조적 방어)
- **출제**: 문제 문장을 넘겨야 하므로 **지시문으로만 막고 있다.** 모델이 답을 안다

출제 경로는 지금 0건이지만 **보장이 아니다.** 프롬프트를 고칠 때마다 다시 봐야 하는 자리다.

## 남은 것

- 이 스크립트들은 수동 실행이다. **CI에 붙어 자동으로 도는 회귀는 아니다**
- 사람 검수 113건이 대기 중이다. 라벨이 뒤집히면 위 수치가 바뀐다
- 판정 정확도는 라벨 기준이지 "실제 사용자가 만족하는가"가 아니다
